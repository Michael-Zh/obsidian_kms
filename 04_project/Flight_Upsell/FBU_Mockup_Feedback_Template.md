# FBU Mockup Feedback Collection — Communication Templates

## Part A: Reusable Framework (Any Mockup)

### Q&A Template for FBU

```
Hey, looked through the mockups — quick alignment before I send to regions. Just reply with numbers 🙏

1. Any design decisions already locked? (tech constraints / timeline / design system / ABT results)
2. If there are multiple versions — which A/B tradeoff is the core one? Which side are you leaning toward?
3. Any compliance risks for strict-compliance markets (AF/KL, AA/DL/LH domestic)?
4. Any overlap or conflict with existing ABT results we should be aware of?
5. [Insert one question specific to this mockup's core change]
6. What are you most unsure about? Which scenarios or markets should regions focus on?

I'll turn your answers into a structured feedback request before sending to regions.
```

**How to write Q5:**
- Seize the single most important change in the mockup and ask how it relates to a known project pain point
- Template: `This change vs. [known pain point] — does it fix it, is it independent, or could it conflict?`
- Examples:
  - Fare card redesign → "With key benefits pulled upfront, is the refundability differentiation signal stronger or weaker?"
  - Ranking/filtering → "Under the new ranking logic, will higher-priced Flexible tiers get pushed further down?"
  - Price display → "With total-price display, will add-on cost breakdown still be transparent to users?"

### Design Principles

| Principle | Why |
|---|---|
| ≤ 6 items | Any more, they won't read |
| < 20 chars per item | Scannable in one glance |
| Expected reply < 10 chars | Low psychological burden to respond |
| Q5 is a fill-in-the-blank | Write one specific question per mockup |
| Skip background context | They're already looking at the mockup — zero context needed |
