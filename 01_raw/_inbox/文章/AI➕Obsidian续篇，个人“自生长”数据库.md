# AI➕Obsidian续篇，个人“自生长”数据库

距离上一篇过去 20 来天，是时候把"自生长"知识库基础版搭起来、回来交作业了。今天这篇就是来还当时立下的 flag。

其一：Syncthing 把 PC + 移动端连接起来

上一篇还停留在"对比坚果云 vs Syncthing"的纠结阶段，最后选了 Syncthing，理由只剩一句话：纯本地 P2P 同步，数据不上第三方，沿用原生文件夹结构，实时双向增量。

实际配起来没多少坑：

\- PC 端装 Windows 版，移动端装安卓版，两端加设备 ID 后建共享文件夹。  
  
\- PC 端路径直接指向 \`D:\\pig\_brain\`，移动端选到 Obsidian 的 vault 目录。  
  
\- 在 WiFi 或移动数据下，两边状态基本实时同步。  
  
\- 文件版本控制默认开启，回收站保留60天，作为兜底。  
  
配完之后 PC 端"最新"状态、移动端"最新"状态，速率都跑到空闲档，证明全部文件已经对齐。这次把整个 AGENTS.md、README.md、整个 raw/资料库、wiki/ 知识库全同步过去了 -- 我随时在 PC 上写的笔记、扫回来的资料，手机打开 Obsidian 就能看到，反过来也一样。

### 其二：用 WorkBuddy + Obsidian，把 AI 时代的知识闭环跑通了

上一篇只说了"Obsidian 是 Markdown 原生，AI 易读取"，但怎么真正把这件事落地没说清楚。这一篇补上——核心是两个文件 + 一个 AI 引擎。

#### AGENTS.md —— Wiki 的"宪法"

如果说整个 Wiki 是一个国家，AGENTS.md 就是宪法。它一次性把所有规矩定义清楚：

-   三层目录结构怎么划分（raw / wiki / schema）。
-   三种操作（Ingest / Query / Lint）每一步的具体流程、产出文件、哪里允许自由发挥、哪里禁止改动。
-   文件命名（kebab-case）、frontmatter 字段顺序、交叉引用的写法。
-   甚至连 raw 子目录（clippings / daily / redbook）的物理划分都登记清楚。

目录结构

```
D:\pig_brain\
│   AGENTS.md        # 本规范文件（schema）
│   README.md        # Wiki 总览与入口说明
│
├───raw/             # 原始资料（只读，不可修改）
│   ├───clippings/   # 外部策展文章（网页剪藏、转载、他人作品）
│   ├───daily/       # 个人每日复盘（思考记录、故障排查、经验总结）
│   ├───redbook/     # 个人小红书内容（创作/发布图文或创作素材）
│   └───assets/      # 图片、附件等
│
└───wiki/            # LLM 生成的 Wiki（LLM 拥有）
    │   index.md     # 内容目录（按类别罗列所有页面）
    │   log.md       # 操作日志（按时间追加）
    │   overview.md  # 高层总览
    │   synthesis.md # 演进式综合 / 论题（随资料增长而修正）
    │
    ├───entities/    # 实体页（人物、组织、产品、地点...）
    ├───concepts/    # 概念页（理论、方法、术语...）
    ├───comparisons/ # 对比页（A vs B）
    ├───sources/     # 单来源摘要页（对应 raw/ 中的每份资料）
    └───templates/   # 页面模板（entity / concept / comparison / source）
```

关键意义：每一个新会话接手的 LLM，读 AGENTS.md 就能立刻进入节奏——知道自己能做什么、不能做什么、做完去哪儿登记。把"经验"沉淀成"规矩"，不用每次都重新教，省下的是反复拉扯的时间。

#### README.md —— Wiki 的"门面"

README 是入口说明，把整套理念 30 秒讲完：

> 不是每次都从原始文档重新发现知识，而是让 LLM 持续构建并维护一个持久、可复利增长的 Wiki。

这一句话决定了下一步所有的行为——我（人类）只负责把原始资料放进 raw/，剩下的 schema 怎么定、Wiki 怎么维护，AGENTS.md 已经替我想好了。README 与 AGENTS 之间形成"门面 → 宪法"的承重，任何新加入的 LLM 都能在这个体系下不偏离。

README

```
# LLM Wiki

一个基于 Karpathy LLM Wiki 方法论构建的个人知识库。

**理念**：不每次查询都从原始文档重新发现知识，而是让 LLM 持续构建并维护一个持久、可复利增长的 Wiki——结构化、相互链接的 Markdown 文件集合。

## 三层架构

| 层 | 目录 | 谁拥有 | 作用 |
|---|---|---|---|
| Raw（原始资料） | raw/ | 你（只读） | 文章、论文、图片、数据等源文件，不可修改 |
| Wiki（知识库） | wiki/ | LLM | 摘要、实体页、概念页、对比页、综合 |
| Schema（规范） | AGENTS.md | 你 + LLM | 告诉 LLM 如何组织、约定与流程 |
```

#### WorkBuddy —— Wiki 的"AI 维护员"

LLM 时代，个人知识库最大的变量是 AI 会不会主动维护。WorkBuddy 是我目前用的执行引擎，跑在 PC 端。它每次接手 Wiki 先读 AGENTS.md 与 README.md，再动手。核心三件事：

-   摄取（Ingest）：读 raw/ 新资料 → 写 wiki/sources/ 摘要 → 更新相关概念 / 实体页 → 登记 wiki/index.md → 记一笔到 wiki/log.md。
-   查询（Query）：先读 wiki/index.md 定位相关页面，再下钻综合。
-   检查（Lint）：跨页面矛盾、孤立页、缺失引用都让它主动扫描。

#### 三种操作（Operations）

**1\. Ingest（摄取）**

你把一份新资料放入 raw/，并让 LLM 处理它。建议流程：

1.  阅读 raw/ 中的源文件。
2.  与你讨论关键要点（takeaways）。
3.  在 wiki/sources/ 写一份该来源的摘要页（用 templates/source.md）。
4.  更新 wiki/index.md：把新页面登记进对应类别。
5.  更新相关的实体页 / 概念页 / 对比页 / 综合页（一份来源可能牵动 10-15 个页面）。
6.  在 wiki/log.md 追加一条 ingest 记录。
7.  推荐一次摄取一份、保持参与；也可以批量摄取、减少监督。把你的偏好写进本文件。

**2\. Query（查询）**

你向 Wiki 提问。建议流程：

1.  先读 wiki/index.md，定位相关页面。
2.  深入读取相关页面。
3.  综合回答并附引用（链接到具体页面）。
4.  答案形式可多样化：Markdown 页、对比表、Marp 幻灯片、图表（matplotlib）、canvas。
5.  好答案应回写进 Wiki 成为新页面——你求得的对比、分析、发现的关联，都是宝贵资产，不应消失在聊天历史里。这样你的探索也能像摄取的来源一样在知识库中复利增长。

**3\. Lint（检查）**

定期让 LLM 对 Wiki 做健康体检，重点查找：

-   页面之间的矛盾 / 新来源已推翻的旧结论。
-   孤立页面（无任何入链）。
-   被多次提及但尚无独立页面的概念。
-   缺失的交叉引用。

真正用起来最直接的体感：资料进 raw/ 后不再"躺死"。每新进一篇，WorkBuddy 顺手把它关联到的概念、实体、对比 10-15 个页面一起更新。我自己几乎不参与维护——只是把原始资料交过去，剩下的活它接过去。

### 其三：图谱里长出来的"自我证明"

最后一张是 Obsidian 的关系图谱，我自己看了挺有感触。

最初我以为 Wiki 就是"文件夹 + 标签"——把文章归类贴标签，方便以后搜索。图谱出来之后我意识到自己低估了双向链接 + 概念抽取这两件事的力量：

-   同一句"机制对抗惰性"，原本孤立出现在第一篇红书笔记里，结果它第二次、第三次出现时 LLM 就把它抽成独立的概念页。
-   "私有个人数据是 AI 时代最珍贵资产"这个判断，原本只在一篇笔记里出现过，现在已经被 Wiki 的综合页（synthesis）单独提炼。
-   心理学的"蔡格尼克效应"和工作上的"机制对抗人性"，原本跨学科的事，因为 Wiki 的双向链接在图谱上自然连在了一起。

图谱意外告诉我：只要我把规则定得足够清楚，把维护托给 AI，"我脑子里反复出现的真正重要的事"会自己长出来，并不需要我主动去组织它。这正是上一篇想搭建的"自生长"——落地了。

而且回看上一篇留下的"机制对抗惰性"的呼吁，这篇的搭建过程本身就是用这套机制反过来帮自己把上一篇的设想落地的过程——我没有靠意志力硬撑，每天靠的是 AGENTS.md 这套机制 + WorkBuddy 这个 AI 在持续推进。这件事本身就算上一篇笔记的一次自我验证。

### 下一步计划和思考

知识库是搭起来了，但我还停在"收藏夹吃灰"的状态——AI 很轻松就能把这些知识管得井井有条，可我反而容易被"善于收藏"这个动作骗到：存下来的，并不真的是我的。真正属于我的，是能随时被抽取出来、连成网络、落在实处的知识。

所以往后我想走两条路：一是去公开平台做持续输出，逼自己把知识用出去；二是常和自己的知识库对话，在已有的 Wiki 里不断反问、讨论。这样的知识，才真正"长"在自己身上。

以上便是"自生长"数据库从构想到跑通的全部过程，与各位共勉。
